# Third-party risk assessment: Vercel, Inc.

| | |
|---|---|
| **Vendor** | Vercel, Inc. (vercel.com) |
| **Service assessed** | Vercel platform: hosting, build and deployment, edge network/CDN, serverless and edge functions, WAF, runtime logs |
| **Requesting team** | Engineering (hosting for customer-facing web applications) |
| **Assessor** | Daniel Chavez |
| **Assessment date** | 2 September 2026 |
| **Method** | Public-source review only: vendor trust center, documentation, DPA, ToS, SLA, status and incident bulletins. No questionnaire was sent and no SOC 2 report was read. Items that can only be settled by reading the report are marked as such. |
| **Related control** | RSK-02 Vendor risk management (satisfies SOC 2 CC9.2, CC2.3) |

## 1. Scope and inherent risk

**What the vendor does for us.** Hosts the production web application and marketing site, runs the build pipeline from GitHub, terminates TLS, serves the CDN, executes server-side functions, and holds environment variables including API keys for downstream services.

**Data the vendor touches.**

| Data class | Examples | Present? |
|---|---|---|
| Restricted | Payment card data | No (payments handled by a separate PCI provider; Vercel serves the checkout page only) |
| Confidential | Customer PII in transit through functions; environment secrets; source code at build time | Yes |
| Internal | Runtime logs, analytics, build logs | Yes |
| Public | Static site content | Yes |

**Inherent risk tiering** (before controls).

| Factor | Rating | Rationale |
|---|---|---|
| Data sensitivity | High | Confidential PII transits the platform; secrets are stored there |
| Access to our environment | High | Holds deploy keys for production, reads the GitHub repo, and holds third-party API keys |
| Business criticality | High | If Vercel is down, the product is down |
| Substitutability | Medium | Migration to another Next.js host is feasible in weeks, not days |
| Regulatory exposure | Medium | GDPR applies to EU customers; no PCI or PHI scope |

**Inherent risk: Tier 1 (critical).** Full review required before onboarding and annually thereafter; SOC 2 report must be obtained and read.

### 2.8 Fourth parties

The April 2026 incident originated at a fourth party (an AI tool used internally), which is the concentration risk made concrete.

## 3. Findings

| ID | Finding | Severity | Basis |
|---|---|---|---|
| F-01 | Confirmed security incident (April 2026) originating from a third-party AI SaaS tool with access to employee accounts; some customer environment variables potentially exposed. Response and disclosure were prompt and public. | High | Vendor bulletin |
| F-02 | DPA breach-notification commitment is "without undue delay" with no numeric window. Our own incident response plan (OPS-03) assumes 72-hour GDPR notification, which requires vendor notice well inside that. | High | DPA |
| F-03 | Subprocessor objection window is 5 calendar days and notification is by list update unless we subscribe to email notice. Easy to miss. | Medium | DPA §7.3 |
| F-04 | No contractual EU data-residency guarantee; primary processing in the US; functions default to a US region unless configured. | Medium | DPA, regions docs |
| F-05 | Default runtime log retention (1–3 days) is far below the 12 months our logging control (OPS-02) requires. | Medium | Runtime logs docs |
| F-06 | Audit logs are Enterprise-only and their retention period is not stated. On Pro we have no audit trail of who changed what in the Vercel dashboard. | Medium | Audit log docs |
| F-07 | Single-cloud dependency on AWS, demonstrated by the Oct 2025 us-east-1 cascade. Vercel's failover is within AWS. | Medium | Compliance docs, post-mortem |
| F-08 | The SOC 2 Type II report has not been read. Exceptions, complementary user entity controls (CUECs) and the auditor's opinion are unknown. | Medium (process) | This assessment |
| F-09 | Data deletion at termination is "commercially reasonable", not a fixed period, and Vercel may terminate on 30 days' notice. | Low | DPA, ToS |
| F-10 | Public security page cites ISO 27001:2013 while the trust center cites 27001:2022. Housekeeping, but a sign to verify certificates directly with the auditor's register. | Low | vercel.com/security |

## 4. Residual risk and recommendation

Vercel's control environment is mature for its size: current SOC 2 Type II and ISO 27001:2022, a public DPA with SCCs, strong platform-layer protection against framework CVEs, a real SLA on Enterprise, and unusually transparent incident reporting. The April 2026 incident is serious but the disclosure and remediation behaviour is what a good vendor looks like under pressure; the risk it exposes (SaaS tools with broad access inside the vendor) is one we should ask about directly.

**Residual risk: Medium.** **Recommendation: Approve with conditions.**

Conditions before go-live, in priority order:

1. Obtain and read the 2026 SOC 2 Type II report; record exceptions and map every CUEC to one of our controls (closes F-08).
2. Send a short supplementary questionnaire covering: numeric breach-notice window they will commit to in an Enterprise DPA (F-02); what changed in third-party SaaS access governance after April 2026 (F-01); audit log retention (F-06); pentest cadence.
3. Enterprise plan or equivalent contractual terms for: 99.99% SLA, audit logs, Trusted IPs, and a negotiated breach-notice window (target 24–48 hours).
4. Configure: SAML SSO enforced, 2FA enforced, log drains to our log platform for 12-month retention (F-05), functions pinned to the region matching our customers (F-04), all secrets marked Sensitive so they cannot be read back in plaintext (F-01), and a subscription to subprocessor notices at privacy@vercel.com with the 5-day window on the compliance calendar (F-03).
5. Document an exit plan: repo is the source of truth; DNS, environment variables and log exports are the three things that must be recoverable in 30 days (F-09, F-07).
